# History file and live dashboard

The history file holds every number the climb produced, in time order. The dashboard is only a view of it: never edit the page, regenerate it. You read the file after a context reset; the user watches the page.

## Layout in a project

```
perf/
├── perf-budget.txt            lab ceilings (ratchet.md)
├── perf-history.jsonl         the history: commit it
├── perf-dashboard.html        generated by dashboard.ts: gitignore it
├── perf-dashboard.data.js     rewritten on every history write: gitignore it
└── ratchet.ts, history.ts, dashboard.ts, dashboard.template.html
```

## One line per measurement

```json
{"t":"2026-10-08T19:40:00Z","kind":"field","key":"api.notes_list","value":410,"stat":"p95","unit":"ms","n":48000,"version":"2.2.0"}
{"t":"2026-10-11T20:00:00Z","kind":"field","key":"battery.life","value":300,"unit":"days","better":"higher","source":"estimate","note":"awake time x datasheet current"}
{"t":"2026-10-12T12:00:00Z","kind":"lab","key":"api.notes_list.queries","value":2}
{"t":"2026-10-09T10:44:29Z","kind":"ceiling","key":"api.notes_list.queries","value":3,"version":"a1b2c3d"}
{"t":"2026-10-08T13:41:00Z","kind":"event","label":"Batch-load tags for the notes list","type":"release","version":"2.3.0"}
```

| Field | Meaning |
|---|---|
| `t`, `kind` | always required. `kind` is `field`, `lab`, `ceiling` or `event` |
| `key`, `value` | required except on events. Values are costs, so lower is better unless `better` is `"higher"` |
| `stat` | for field results: `p50`, `mean`, `p95`… Each statistic keeps its own color in every chart. `before` marks a lab value from before the fix |
| `source` | `measured` (the default), `simulated`, `estimate` or `datasheet`. Anything not measured is drawn hollow and left out of the headline |
| `version`, `n`, `unit`, `note` | shown in tooltips and tables |
| `label`, `type` | events: `release`, `revert` or `note`. Releases and reverts mark every field chart |

## Commands

```bash
# field results, one stat per call (a report script can pipe its numbers straight in)
printf 'api.notes_list 410\napi.note_get 95\n' | bun history.ts field perf-history.jsonl - --version 2.3.0 --stat p95 --unit ms --n 48000
# lab: records ceilings and counts that changed since the last call; safe to run after every test run
bun history.ts lab perf-history.jsonl perf-budget.txt test.log
bun history.ts event perf-history.jsonl "Cache permissions per request" --type release --version 2.4.0
# past ceilings from the budget file's git history, plus each `# <before>: <why>` comment as a before value
bun history.ts backfill perf-history.jsonl perf-budget.txt
bun dashboard.ts perf-history.jsonl --title "notes-api"
```

`--t <ISO date>` backdates any `field`, `lab` or `event` entry, for importing results the perf doc already records.

## Wiring it in

- **Lab:** append `bun perf/history.ts lab perf/perf-history.jsonl perf/perf-budget.txt <test log>` to the project's run-all script, after the budget check. It only writes when something changed.
- **Field:** have the report script finish with one `history.ts field` call per statistic, or run them by hand from its output. Record the release event when a version ships, not when its results come in.
- **Before values:** write budget comments as `# <value before the fix>: <why>`. `backfill` then shows each budget's drop from before the fix, not just from when the budget was added.

## How the page stays current

- `perf-dashboard.html` is static. It loads `perf-dashboard.data.js` as a script and reloads it every 2 s with a cache-busting query.
  - It redraws only when the history's hash changes.
  - It works from `file://`, where `fetch()` is blocked, and from any static server.
- `history.ts` rewrites the data file on every write, but only if `perf-dashboard.html` sits next to the history file. Projects that never ran `dashboard.ts` get no extra files.
- The header says "Live" while the data loads, and "Not updating" when the data file has stopped loading (it was deleted or moved, or the page was opened from another folder).

## What the page shows

- **Headline:** the geometric mean of first → latest across field metrics, using each metric's headline statistic (mean, then p50, p75, p95, p99). Estimates are excluded.
- **A tile per field metric:** the latest value, and the change since the first result.
- **A chart per field metric:** one line per statistic, release markers, a hover crosshair (also reachable with the arrow keys), and a table view.
- **Lab budgets:**
  - before → now, sorted by reduction
  - the latest lab count, flagged when the ceiling could be lowered
  - a step chart of each ceiling over time
- **Timeline:** releases, reverts and notes.
